# فروش‌یار — فاز آزمایشی مکالمه نوبتی تلفنی v0.2

**وضعیت:** بسته آزمایشی، برای داخلی 300 در Grandstream UCM6202. استفاده در محیط عملیاتی عمومی توصیه نمی‌شود. تنها پس از تست با داخلی محدود، امکان پذیرش تماس مشتریان را بررسی کنید.

## کارکرد

- Asterisk مستقر در کانتینر `forushyar-sip-test` همچنان SIP/RTP را مدیریت می‌کند.
- به‌جای پخش پیام و قطع، Dialplan به یک FastAGI محلی به نام `forushyar-voice-pilot` متصل می‌شود.
- فروش‌یار پیام خوشامدگویی سابق را پخش می‌کند، از مشتری حداکثر ۱۰ ثانیه ضبط می‌گیرد و تا ۲ ثانیه سکوت را برای اتمام نوبت انتظار می‌کشد.
- Whisper فارسی را به متن تبدیل می‌کند، Qwen 4B یک پاسخ کوتاه محاوره‌ای می‌سازد و Piper آن را به WAV تبدیل می‌کند.
- پاسخ از طریق تلفن پخش می‌شود. حداکثر ۳ نوبت در هر تماس فعال است.
- مکالمه **نوبتی** است، نه پخش جریانی هم‌زمان؛ پاسخ ممکن است چندین ثانیه طول بکشد.
- **قیمت واقعی، موجودی لحظه‌ای، سفارش، انتقال تماس، اتصال CRM، و ثبت نتیجه تماس وجود ندارند.** پاسخ‌ها صرفاً آزمایشی‌اند.
- صدای خام و فایل‌های پاسخ به‌شکل موقت روی دیسک محلی ذخیره و در پایان نوبت/تماس حذف می‌شوند. متون مکالمه در پایگاه داده ذخیره نمی‌شوند؛ با این حال محتوا در حافظه سرویس‌ها هنگام پردازش وجود دارد.

## پیش‌نیاز

- سرویس‌های `smart-sales-ai-api-1`, `smart-sales-ai-speech-1`, `smart-sales-ai-ollama-1` سالم باشند.
- تنظیمات داخلی 300 با نسخه `forushyar-sip-test-v01` قبلاً کار کرده باشد و تماس خوشامدگویی پخش شده باشد.
- محل اجرای دستورات باید Debian با دسترسی Docker باشد؛ نیاز به pull یا build ایمیج جدید وجود ندارد.
- شبکه خصوصی Compose با نام پیش‌فرض `smart-sales-ai_private` باید موجود باشد؛ در صورت تفاوت، `FORUSHYAR_DOCKER_NETWORK` را مشخص کنید.
- فایل `~/.config/forushyar-sip-test/extensions.conf` هنوز الگوی v0.1 باشد.

## نصب

در Debian، ZIP را در `~/forushyar-AI` کپی و استخراج کنید. سپس:

```bash
cd ~/forushyar-AI/forushyar-voice-pilot-v02
bash install.sh
```

در این مرحله سرویس جدید **فقط** روی `127.0.0.1:4573/TCP` منتشر می‌شود، به شبکه خصوصی Compose وصل می‌شود و **فقط** dialplan کانتینر آزمایشی Asterisk را تغییر می‌دهد. هیچ فایل `.env`، جدول PostgreSQL، container اصلی API، PBX، Ring Group یا اطلاعات SIP تغییر نمی‌کند.

نخست از یک داخلی تست شماره 300 را بگیرید. پیام فارسی قبلی را باید بشنوید. پس از بوق بگویید: «سلام، رابیتس ۱۳ ستون دارین؟» و پس از پاسخ، سؤال دوم را مطرح کنید. **مدت پردازش روی CPU ممکن است محسوس باشد.**

## عیب‌یابی

```bash
docker ps --filter name=forushyar-voice-pilot
docker logs --tail 80 forushyar-voice-pilot
docker exec forushyar-sip-test asterisk -rx 'pjsip show registrations'
docker exec forushyar-sip-test asterisk -rx 'dialplan show 300@from-ucm'
```

لاگ‌های این بسته با هدف عدم نمایش محتوای مکالمات طراحی شده‌اند. با این حال قبل از انتشار لاگ‌ها، داده‌های حساس را بررسی کنید.

اگر تماس پس از خوشامدگویی قطع شد، مشکل می‌تواند از ارتباط FastAGI، مجوز فایل ضبط، پردازش Whisper، Qwen یا Piper، شبکه Docker، یا کدک صوتی باشد. خروجی تست‌ها را بررسی کنید. در صورت شکست اجرای `install.sh`، اگر `dialplan` ویرایش شده است، `rollback.sh` را اجرا کنید.

## بازگردانی به فاز قبلی

```bash
cd ~/forushyar-AI/forushyar-voice-pilot-v02
bash rollback.sh
```

این دستور dialplan قبلی (فقط پخش خوشامدگویی) را بازمی‌گرداند و فقط کانتینر `forushyar-voice-pilot` را حذف می‌کند. اتصال SIP داخلی 300 و سرویس‌های اصلی دست‌نخورده می‌مانند.

## ملاحظات امنیتی و محدودیت‌های مهم

- فعلاً این داخلی را برای آزمایش محدود نگه دارید؛ پیش از ارائه عمومی، رضایت/اطلاع‌رسانی ضبط مکالمه، سیاست حفاظت داده و محدودیت دسترسی را تعیین کنید.
- Asterisk در حالت host network است؛ FastAGI فقط روی loopback میزبان منتشر می‌شود.
- هیچ فایل حاوی رمز SIP در ZIP موجود نیست؛ رمز SIP فقط در تنظیمات محلی قبلی قرار دارد.
- فعلاً اتصال CRM و قیمت‌ها غیرفعال است تا مدل پاسخ‌های ساختگی یا تأیید سفارش اشتباه ندهد.
- هیچ فایل voice از تماس مشتری در Git ذخیره نکنید.
- تولید و پردازش مکالمه هنوز جایگزین اپراتور انسانی در تماس‌های حساس نیست.
