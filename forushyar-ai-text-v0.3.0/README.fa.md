# فورش‌یار 0.3.0 — CRM و فروشنده هوشمند متنی

این بسته یک به‌روزرسانی افزایشی روی نسخه نصب‌شده 0.2.0 است. فایل‌های Docker Compose، Dockerfile، `.env` و Volumeهای PostgreSQL/Redis را بازنویسی نمی‌کند.

## قابلیت‌های نسخه

- ثبت و جستجوی مشتریان
- ایجاد و مدیریت گفتگوهای متنی و مشاهده تاریخچه پیام‌ها
- ارجاع گفتگو به اپراتور انسانی (`HANDOFF_REQUIRED`)
- ثبت قیمت جاری کالا همراه با سابقه قیمت‌های قبلی و کد ارز صریح
- درگاه اتصال به هر سرویس مدل زبانی سازگار با OpenAI Chat Completions؛ از جمله سرویس ابری یا درگاه محلی سازگار
- پاسخ‌گویی فارسی با بازیابی محدود و مستند از کاتالوگ، قیمت ثبت‌شده و مانده‌های ثبت‌شده سه انبار
- ذخیره تاریخچه مکالمات
- دستیار این نسخه فقط خواندنی است و سفارش، پرداخت، موجودی یا فاکتور را تغییر نمی‌دهد

## پیش‌نیاز

- نسخه فعلی API: 0.2.0
- PostgreSQL و Redis سالم
- `httpx` از قبل در requirements نسخه پایه وجود دارد

## نصب روی Debian

فایل بسته را به سرور منتقل و در پوشه موقت باز کنید:

```bash
mkdir -p /tmp/forushyar-v030
 tar -xzf ~/forushyar-ai-text-v0.3.0.tar.gz -C /tmp/forushyar-v030
cd ~/forushyar-AI
bash /tmp/forushyar-v030/install_ai_text_v0.3.0.sh
```

اسکریپت قبل از کپی کد از سورس و دیتابیس پشتیبان می‌گیرد؛ سپس image را می‌سازد، Migration `0003_crm_ai_text` را اجرا و API را به‌روزرسانی می‌کند. اگر backup دیتابیس ناموفق باشد، کپی کد و migration انجام نمی‌شود.

## تنظیم اتصال مدل زبانی

این بسته `.env` را تغییر نمی‌دهد. برای فعال‌سازی AI متنی، در فایل `.env` روی سرور این متغیرها را تنظیم کنید:

```dotenv
LLM_BASE_URL=https://YOUR-OPENAI-COMPATIBLE-ENDPOINT/v1
LLM_MODEL=YOUR_MODEL_NAME
LLM_API_KEY=YOUR_PROVIDER_SECRET
LLM_TIMEOUT_SECONDS=45
ASSISTANT_HISTORY_LIMIT=12
```

- کلید API را در گفتگو یا ترمینالِ قابل‌اشتراک ارسال نکنید.
- برای مدل محلی، `LLM_BASE_URL` می‌تواند آدرس داخلی سرویس سازگار OpenAI در شبکه Docker باشد و در صورت عدم نیاز، `LLM_API_KEY` خالی بماند.
- بعد از تغییر `.env`، فقط API را بازسازی/راه‌اندازی مجدد کنید:

```bash
docker compose up -d --build api
```

و وضعیت را بررسی کنید:

```bash
curl -sS -H "X-API-Key: $API_KEY" http://127.0.0.1:8000/api/v1/assistant/status
```

تا وقتی `LLM_BASE_URL` و `LLM_MODEL` تنظیم نشده‌اند، `/assistant/status` مقدار `configured=false` می‌دهد و `/assistant/chat` با 503 پاسخ می‌دهد. این رفتار عمدی است؛ سیستم پاسخ ساختگی تولید نمی‌کند.

## APIهای اصلی

تمام مسیرها نیازمند `X-API-Key` هستند.

### مشتری

`POST /api/v1/customers`

```json
{
  "full_name": "مشتری نمونه",
  "phone": "+989121234567",
  "email": null
}
```

`GET /api/v1/customers?q=نمونه`

### ثبت قیمت کالا

`POST /api/v1/products/{sku}/prices`

```json
{
  "amount": "1250000.00",
  "currency_code": "IRR",
  "source": "MANUAL",
  "notes": "قیمت اعلام‌شده توسط مدیر"
}
```

در این API واحد پول باید صریحاً ثبت شود؛ سامانه بین ریال و تومان حدس نمی‌زند. با ثبت قیمت جدید، قیمت قبلی غیرفعال می‌شود ولی در تاریخچه باقی می‌ماند.

### وضعیت دستیار

`GET /api/v1/assistant/status`

### گفتگوی متنی هوشمند

`POST /api/v1/assistant/chat`

```json
{
  "message": "موجودی کالای با کد P-100 در کدام انبارها ثبت شده؟",
  "customer_id": null,
  "conversation_id": null
}
```

پاسخ، شناسه گفتگو، شناسه پیام‌ها، متن پاسخ و SKUهای استفاده‌شده برای grounding را برمی‌گرداند. برای ادامه گفتگو، `conversation_id` پاسخ قبلی را ارسال کنید.

## محدودیت‌های مهم این نسخه

- برای پاسخ واقعی AI باید یک مدل و endpoint سازگار پیکربندی شود؛ این بسته هیچ کلید یا مدل ابری از پیش‌فرضی ندارد.
- دستیار فقط از داده‌های ثبت‌شده کاتالوگ، قیمت و مانده انبار استفاده می‌کند. اگر قیمت یا مانده در سیستم ثبت نشده باشد، نباید آن را حدس بزند.
- این نسخه ثبت سفارش، تأیید پرداخت، فاکتور، تخفیف، هزینه ارسال و عملیات نوشتن روی انبار را از طریق هوش مصنوعی انجام نمی‌دهد.
- API فعلی از یک کلید مشترک `X-API-Key` استفاده می‌کند. پیش از استفاده با اطلاعات واقعی مشتری در محیط عمومی، TLS، کاربران/نقش‌ها، کنترل دسترسی سطح رکورد، محدودیت نرخ و سیاست نگهداری داده باید تکمیل شوند.
- صدای زنده و SIP در این نسخه نیستند؛ فاز صوتی بعدی پس از تثبیت دستیار متنی انجام می‌شود.
